# 核心实验

> 这里的 8 个 Lab 默认都是**形成性学习资源**，不是 8 次正式作业。Lab 可以只用于辅助学习，也可以由课程组在正式作业说明中明确指定为某次作业的一部分；是否计分以教师发布的作业要求为准。公开状态见 [`catalog.json`](catalog.json)。

每个实验包含任务说明、`starter.py` 和 `test_lab.py`：

- `starter.py` 是未完成的起始代码。在 PAI-DSW 快速开始 Notebook 中运行 `init_lab("<lab-id>")`，把它复制为 `student-work/labs/<lab-id>/solution.py`；只修改学生副本，已有副本不会被覆盖。
- `test_lab.py` 是只读公开测试。在 Notebook 中运行 `test_lab("<lab-id>")` 检查学生副本，不要通过修改测试来制造“通过”。公开测试提供学习反馈，但不保证覆盖所有边界条件或工程风险。

当 Lab 未被指定为计分任务时，它可用于自由练习并在完成尝试后查看完整解析；一旦被正式指定为作业组成，OpenCode 只提供分级提示、相似新例、测试建议和已有代码评审。

推荐流程：先预测测试结果 → 写最小实现 → 运行公开测试 → 解释失败原因 → 修改 → 用新输入验证。OpenCode 使用 `/lab <编号>`，只提供分级提示，不直接填写完整实现。

教师开发或没有云环境时，可在仓库根目录使用 `uv run python code/runner.py lab init <lab-id>` 与 `uv run python code/runner.py lab test <lab-id>` 作为本地降级入口。

函数的 docstring 是公开接口契约：实现应保持函数名、参数、返回值、错误类型和“不修改输入”等约束。测试只是契约的样例，不是完整规格；公开测试通过后，每个函数还应自拟至少一个正常、边界或失败输入。下表时间是首次独立完成的学习估计，不是正式课时或限时标准。
