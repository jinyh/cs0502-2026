# 分组转发与路由计算：六分钟课堂讲法

[打开演示](packet_routing.html) · 配合2026版第12课P8–10。页面可直接双击，离线运行，无需安装依赖。

## 先预测，再推进

- 约2分钟，阶段①：先问“分组的目的地是T，到了N1该交给谁？”单步观察到达、读目的地、查表命中、选下一跳和沿链路发送。按课件给定表得到 `S→N1→N3→N2→N4→T`，处理时延累计20 ms。这里只显示当前路由器到T的一条表项，是课堂模型，不是完整的真实IP转发表。
- 约2分钟，阶段②：问“如果希望路由器间跳数最少，转发表应该怎样改？”从T接入的N4开始运行Dijkstra。每条路由器间链路代价均为1，先取距离最小的候选，再逐条松弛。距离相同时按节点名称排序。确定顺序为N4、N2、N1、N3，到N4的距离分别为0、1、2、2。前驱指向N4，因此可以生成各节点到T的下一跳。
- 约2分钟，阶段③：计算结束后由教师主动切换，重新发送。新路径 `S→N1→N2→N4→T`，处理时延12 ms。追问“分组自己算了最短路吗？”答案是各路由器使用已经生成的表。

## 教学边界

- 网络是无向教学图，S接入N1，T接入N4。路由器间链路为N1–N2、N1–N3、N2–N3、N2–N4。没有N1–N4链路。
- 最短路按路由器间链路跳数计算，主机接入链路不计入这个指标。Dijkstra以目的端N4为根的集中演示解释表的来源，不模拟真实分布式路由协议的消息交换与收敛。
- 给定表是课件练习输入，并不按本例最少跳数选择。路由阶段重新计算后才生成新表，分组转发阶段不重新运行算法。
- N1、N2、N3、N4的处理时延分别为4、6、8、2 ms。20 ms与12 ms只累计处理时延，未计发送、传播、排队等时延。动画速度仅为显示速度。
- 本例跳数更少且处理时延更低，不能推广为“最少跳数总是最低实际时延”。路由指标与实际端到端时延是不同量。
- 分组一直显示目的地T；下一跳随路由器改变。真实IP转发涉及目的前缀、接口、最长前缀匹配等内容，本演示不展开。

## 操作

下一步／回退用于逐个事件追踪，空格播放／暂停，方向键单步。预测暂停默认开启，停在首次查表前、取最小候选前及更新距离前。点击“揭示下一步”或再次播放继续。阶段②完成前阶段③不可用，返回阶段②重新计算会撤销新表可用状态。

阶段切换、重置及回退均停止播放。重置只清除当前阶段轨迹。窗口缩小时纵向排列；系统设置减少动态效果时保留状态切换，省略分组平移动画。
