# 路由器转发模型：课程交互演示

[打开演示](packet_routing.html)。配合2026版第12课P8–9，可在课程网站使用，也可直接打开HTML离线使用。

## 课堂讲法

1. 先观察拓扑：C只直连R2。分组横向分为首部与数据，放大图突出源地址C、目的地址D、数据hello；其他首部字段省略。
2. 到达R2后展开R2的多行转发表。读取目的地址D，先预测应匹配哪一行，再揭示查表结果。
3. 橙色将分组头中的D和表中的D对应起来，蓝色将选中接口、下一跳和实际链路对应起来。R2通过接口3交给R3。
4. 分组到达R3，再换成R3的本地表。R3通过接口3交给R4，R4通过接口1直接交给D。已走路径逐步出现为 `C→R2→R3→R4→D`。
5. 将目的地改为E，对照R2仍走接口3、R3仍走接口3，但R4换接口2。改为F，R2则直接从接口4交给R5。讨论：不同目的地可能共用同一下一跳。
6. 最后展开“这些表从哪里来？”，简要说明路由形成和更新信息，转发使用当前本地表，不要求先推导算法。

## 模型数据与边界

拓扑参照2026版第12课P8–9：A、B接R1，C接R2，D、E接R4，F接R5。路由器间连接为R1–R2、R1–R3、R2–R3、R2–R5、R3–R4、R3–R5、R4–R5。

逐跳表项为明确补充的教学配置，不声称整套表都来自课件。每台设备按相邻设备名称排序定义本地接口编号；接口号只在本设备有意义。

| 路由器 | 接口1 | 接口2 | 接口3 | 接口4 |
|---|---|---|---|---|
| R1 | A | B | R2 | R3 |
| R2 | C | R1 | R3 | R5 |
| R3 | R1 | R2 | R4 | R5 |
| R4 | D | E | R3 | R5 |
| R5 | F | R2 | R3 | R4 |

- 源固定为C，目的地可选A、B、D、E、F。A、B经R2、R1送达，D、E经R2、R3、R4送达，F经R2、R5送达。
- 分组在地图中以缩小报文表示，下方是同一分组的放大图。源地址、目的地址和数据在途中保持不变，仅为突出本课的查表过程，并未模拟完整IP首部、TTL变化、NAT或链路层重新封装。
- 目的地A–F是主机标识，不模拟真实IP前缀及最长前缀匹配。不展示时延或将动画速度当成实际速率。
- “转发表形成”是概念示意。真实设备可综合路由协议、路由算法、静态配置等信息生成转发表；本页不模拟协议消息、收敛或Dijkstra演算。

## 操作

- 下一步依次推进：到达、读取目的地址、匹配表项、选接口与下一跳、沿链路发送。到达时不提前高亮命中行。
- 默认在每次读取目的地址后自动暂停，待预测后点击“揭示查表”或再次播放。
- 回退、重新发送和更改目的地均停止播放。更改目的地清除旧路径、当前表及全部高亮。
- 方向键回退／下一步，空格播放／暂停。选择框保持原生键盘操作。
- 窗口较小时，转发表排在网络和放大报文下方。系统启用减少动态效果时跳过报文平移动画，保留逐步状态。
