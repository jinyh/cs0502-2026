观察什么？

先追踪“交错执行”，在 P2 写回后预测 P1 的下一次写回，再对照顺序与加锁两种情况。

读取：把共享 count 复制到自己的寄存器。加一：只修改局部寄存器。写回：把寄存器中已经算好的值保存到 count。

临界区（critical section）是需要协调访问的代码段。加锁保护整个“读—加—写”。两者使用同一把锁；本演示把获取锁视为原子操作。P2 获取失败时等待，不进入临界区。锁的底层实现留到后续案例。

“读”“写”各作为一步，按顺序一致的共享内存模型追踪。动画中的步骤序号表示操作顺序，不表示实际耗时。
