# 无人船巡检交互实验室

[打开独立实验室](index.html) · [二维备用入口](index.html?view=2d) · [开发与验证记录](VALIDATION.md)

服务 CS0502 第 1—2 讲，面向没有编程经验的非计算机专业学生。开场问题：**船回来了，这份巡检报告能交吗？**

## 本地启动

在仓库根目录运行：

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory code/visualizations/usv-inspection
```

浏览器打开 `http://127.0.0.1:8765/`。通过 HTTP 使用 ES modules，不直接双击 `index.html`。本站无构建步骤，运行时无需联网、账号、API Key 或 CDN；Three.js 0.180.0 已随本地资源提供。不要把仓库根目录作为临时服务器的公开目录。

## 第 1 讲：一屏一个问题

课堂模式按同一次航次推进，每屏只有当前问题、证据和一个主要操作。顶部四种思维都可点击切换，并标明当前章节与已完成的操作；观察结果后再用一句话点明概念。详细原理、三维拆解、参数与 Python 都按需展开。

| 当前重点 | 学生先做什么 | 结果如何点明概念 |
| --- | --- | --- |
| 计算思维 | 预测哪条候选路线能完成任务 | 检查覆盖、禁区与返航余量，说明表示、步骤与约束 |
| 系统思维 | 预测断网对记录的影响 | 对比船上与岸站记录，追踪部件分工和信息流 |
| 数据思维 | 先数满足规则的记录，再改变比较符号 | 对比预测与结果，区分来源、规则、次数对象和结论范围 |
| 智能思维 | 看原图保留候选，再看补拍修正判断 | 说明候选、验证、反馈以及还需要什么证据 |

建议课堂操作顺序：

1. **选路线**：先选 A、B 或 C，再检查。A 会出现禁区冲突，C 遗漏 P2；选择 B 后按路线出航。需要讨论任务表示时，展开“看看为什么”。默认 60 Wh、本地执行、4×。
2. **做预测**：到 P1 自动暂停。选择断网后记录会怎样，再点“切断通信并观察”。预测错误也能开展实验。
3. **看断网结果**：本地执行配置在 P2 自动暂停，此时船上 2 条、岸站 1 条。按需展开“看看为什么”，旋转、缩放、展开船体，选择部件查看职责与信号流。
4. **恢复并返航**：先观察补传，岸站变为 2 条；再继续巡检返航。页面分别保留 31 s 的断网证据、32 s 的补传证据，最终在 63 s 返航。
5. **比较统计规则**：当前航次收到 `[65, 80, 81]`。先预测 `>=80` 的次数，验证为 2；随后改为 `>80`，重新预测并验证为 1。来源、规则和预测始终标明。
6. **检查图像**：先看原图和疑似区域，保留候选；改变光照查看补拍。确认裂纹或排除风险都会得到“现有证据不足”的反馈，允许重新判断。选择保留疑点并进一步复检，生成教学报告。
7. **回看四种思维**：报告自动生成四张回顾卡，保留初始预测和实际证据。最后只有一个迁移问题，可口头讨论，也可写下后随报告导出。完整记录放在折叠区。

可随时点击顶部四个章节：系统思维可先查看部件分工，数据思维可直接用标准样例练习，智能思维在未到 P2 时说明还需采集图像，并提供继续任务的按钮。切换会暂停正在运行的航次，保留船位、故障、记录和已经填写的预测；回到相应章节后继续。出航后的计算思维显示当前路线回顾，避免导航误改航线。

不要求逐节填写长学习单。进度勾选表示已走完相应操作，不等于学生已经掌握概念。教师可在结果页停留，让学生用自己的话解释原因。

“实验设置”集中放置暂停、单步、倍速、重跑、恢复基准、电量和执行配置；更复杂的故障组合进入自由探索。课堂模式的当前主要按钮在航行中也可直接暂停或继续。切换自由探索保留当前航次；从自由探索重新进入课堂则恢复基准。

## 第 2 讲：按需展开程序

1. 在课堂数据结果页展开“第二讲 · 展开 Python 程序追踪”；也可直接进入自由探索的“数据与程序”。
2. 展开“更多数据与规则”，一键载入标准课堂数据 `[65, 80, 81]`。它表示同一推进电机 M1 的三个时刻，单位 °C，与航次数据明确区分。
3. 逐句追踪当前温度、条件结果与 `count`。比较 `>=` 与 `>`；改动数据或规则后，课堂模式重新等待预测，当前展开区和输入焦点保留。
4. 比较普通值 `[65, 81]`、边界值 `[80]`、空记录 `[]`；阈值 80 时分别为 1、1、0，完整样例为 2。阈值改为 81 时完整样例返回 1。空记录返回 0，但不能认定设备正常。
5. 下载 [verify_count.py](verify_count.py)，上传 PAI-DSW，在 Notebook 单元运行 `%run verify_count.py`，或粘贴其中函数与验证代码运行。开发验收也使用本机实际 Python 交叉核对。

网页高亮明确标为“教学追踪”，不是 Python 解释器。统计样例与当前航次分别管理；样例选择不改写航次记录，比较符号和阈值是共用规则。因此按默认课堂顺序结束时，报告当前规则为 `>80`、结果为 1；回顾卡同时保留 `>=80` 为 2 和 `>80` 为 1 的依据。OpenCode 只作为可选学习助教；本站没有远程执行接口或大模型调用。

## 自由探索与对照

- 路线：直达穿越禁区；绕行覆盖完整；第三方案遗漏 P2。30 Wh 配置用于检验返航失败。
- 配置：先恢复基准，改为依赖岸站指令，再进行断网实验。此配置失联后暂停推进，传感器与船载记录能力仍在；本模型只在到达巡检点时生成采集记录。
- 供电：船载停机影响感知、计算、写入及推进，已有记录留存。温度传感器缺测只把后续温度记为缺测，不回填过去数据。
- 暂停冻结模拟时间、航行、记录及补传；视角旋转仍可用。复位视角只改相机；重跑当前配置清空航次、课堂过程与复盘；恢复基准同时恢复路线、能量、通信、供电、传感器、倍速、统计和复盘。
- 三维不可用时自动转二维，也可手动切换或使用 `?view=2d`。二维与三维共享全部任务状态、控制和报告。
- 迁移提问：无人机与机械设备的感知、控制和记录放在本地还是远端，会怎样影响失联后的行为？

## 模型假设与限制

- 固定速度 4 m/s；运动耗能 0.10 Wh/m；开机耗能 0.05 Wh/s，停机保留电路耗能 0.01 Wh/s；每个巡检点瞬时采集耗能 1 Wh。
- 60 Wh 基准电量，返航需保留 6 Wh。时间以固定 1 s 步长推进，倍速只改变执行步数。暂停与后台页面不累计时间。
- 返航余量按剩余候选路线的航程、设备开机时间及采集次数估算；等待会消耗电量。禁区矩形边界也算违规。不模拟风浪、水动力、真实避障、传感噪声或电池化学，不宣称最优路径。
- 到达三个巡检点时依次为同一推进电机提供脚本温度 65 / 80 / 81 °C；不把它们冒充实测数据。
- 每教学秒最多交回一条记录，去重、按序补传。返航后补传假设岸站供电。本地存储容量在本次短任务中视为充足。
- “可交教学报告”要求完整覆盖、路线合规、返航余量足够、三条有效温度已交回，并完成 P2 证据查看、选择进一步复检。它允许明确写出未决结论，不代表确认设施安全或确认裂纹。
- 页面刷新不保留航次、课堂过程和复盘；可下载文字报告。源代码程序生成船体几何，不包含真实船型 CAD。
