# 课程项目过程性 Rubric

> 用于学生自查和智能体分级反馈。正式项目若有专用 rubric，以教师发布版本为准。

课程总评中小组项目占 30%。项目成绩必须同时参考小组交付物、个人答辩和个人贡献记录；不能把同一小组分数不加判断地复制给每位成员。具体维度权重和组内调整规则仍需在项目任务书发布前明确。

| 维度 | 达标表现 | 常见失分 |
|---|---|---|
| 问题与需求 | 用户、输入输出、约束、成功标准清楚 | 目标口号化、无法验收 |
| 设计与表示 | 数据结构、组件、接口及算法选择有理由 | 先写代码后补解释 |
| 实现与可读性 | 最小实现可运行，命名和注释服务理解 | 复制复杂代码但不能解释 |
| 测试与证据 | 正常、边界和失败路径均有可重复证据 | 只展示一次成功截图 |
| 分析与责任 | 说明限制、风险、AI 使用和改进方向 | 夸大结论、隐去 AI 贡献 |
| 个人理解与贡献 | 能独立解释关键设计、代码和证据，并说明自己的具体贡献 | 只能复述小组结论，无法解释本人提交部分 |

OpenCode 可以逐项指出证据缺口、运行测试并提出下一步，但不生成可直接提交的完整项目或报告。

## 四级表现描述

| 等级 | 可观察证据 |
|---|---|
| 优秀 | 需求可验收；设计选择有比较；实现、测试和报告可重复；能解释失败边界、AI 贡献与人的责任，并用新证据修正结论 |
| 合格 | 核心功能与主要测试可运行；选择有基本理由；能指出至少一个限制并独立解释关键代码 |
| 发展中 | 有局部实现或说明，但需求、接口、测试或证据链存在关键缺口；对 AI 生成部分解释不足 |
| 尚未达到 | 结果不可运行或不可核验；主要结论无证据；无法解释提交内容，或未披露实质性 AI 贡献 |

本表默认用于形成性反馈；课程总评中的项目占比已确定为 30%，但表内各维度权重尚未定稿。课程组仍需批准最低通过条件、个人贡献调整办法、迟交/协作规则和评分样例，并先做评分一致性校准。

## 使用方式

把自己的代码、测试或报告草稿放在 `student-work/<项目名>/`，再输入 `/project student-work/<项目名>`。智能体只依据能够定位到文件、测试输出或报告段落的证据评审，反馈包括：已有证据、对应 rubric 维度、第一个关键缺口和一个下一步。

若目录中还没有项目文件，智能体只给需求、设计、最小实现、测试证据、可重复运行说明和 AI 贡献记录的准备清单。学生应记录 AI 帮助的范围、采纳或拒绝建议的依据，并能独立解释最终代码和结论。
