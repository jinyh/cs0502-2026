# 前沿进展注记（docs/frontier/）

AI 前沿变化快，写死在卡片里会迅速过期；纯靠智能体联网又可能产生未经审校的失真内容。本目录采用**双层机制**：

1. **静态写底层**（带一手来源、季度检查）— 只有 `review_status: approved` 才可作为课程组批准基线
2. **智能体联网增量区**（动态，每条标注检索日期 + 来源 URL，未经审校）— 学生批判性阅读

## 选材阈值

仅对高变动主题建前沿页：`21-llm`、`16-artificial-intelligence`、`17-machine-learning`、`18-computer-vision`、`20-speech-recognition`、`deep/reinforcement-learning`、`deep/quantum-computing`。

基础稳定主题（数据结构、图灵机、网络协议）**不建**前沿页，避免噪声。

当前已建立并由课程负责人审核通过的静态基线只有：

- [`llm-frontier.md`](llm-frontier.md)
- [`cv-frontier.md`](cv-frontier.md)

两页均保留人工审核角色、日期和范围。`approved` 只批准静态基线的课程使用；正式作业和项目引用仍应回到页面列出的一手论文或官方标准。

选材阈值中的其他主题只是候选，不代表已经存在静态页。智能体找不到 `review_status: approved` 的对应页面时必须明确说“本地无课程组批准基线”，不能用模型记忆补成静态事实。

## 智能体约定

见 `../opencode/AGENTS.md`「前沿检索」一节：
- 询问「最新/进展/2026」时，若对应静态页存在则先读静态层，再联网检索近 12 个月
- 结果以「一句话 + 来源 URL + 检索日期」追加到增量区，**不修改静态层**
- 无已批准静态页 → 先标注无课程组批准基线，再征求联网同意
- 联网失败 → 有静态层时只基于静态层并提示日期边界；无静态层时只保留待验证问题
