# 课程组人工审查清单

本页记录自动检查不能替代的课程决策。它不预设审批结果，也不把一次编辑日期当成人工批准。

## 状态规则

- `needs-review`：尚未完成约定的 AI 全量检查。
- `ai-reviewed`：已完成结构、事实风险、代码/图示、先修和教学适切性检查，但不代表课程负责人或领域专家批准。
- `stable`：必须同时记录 `human_reviewer`、`human_reviewed_at` 和 `human_review_scope`；审查者应具备相应主题或教学评价能力。
- `frontier` 静态页只有 `review_status: approved` 且记录人工审核角色、日期和范围，才是课程组批准基线；学生正式引用仍应回到原始论文或官方标准。当前 LLM 与 CV 两页已通过课程负责人审核。
- `last_reviewed` 只表示最近一次编辑或自动检查，不能作为批准证据。

当前 AI 审核报告见 [`ai-audit-2026-08-22.md`](ai-audit-2026-08-22.md)。

课程组会议可直接使用 [`course-group-review-checklist.md`](course-group-review-checklist.md) 填写教学安排、考试细目、项目规则、讲稿抽查和专家核验结论。

## 需要主题专家批准

- 量子计算：量子信息/量子物理教师复核算法复杂度、测量/纠缠/退相干表述及 PQC 连接。
- 强化学习与 LLM：AI/ML 教师复核 Bellman 方程、RLHF/DPO、长上下文、Agent 与推理模型边界。
- 信息安全：安全教师复核密钥身份绑定、哈希可信来源、威胁模型和考试案例。
- 医学与生物案例：领域教师复核临床外推、监管、患者级划分和风险措辞，避免把研究指标写成可部署结论。

## 每张卡的最小人工审查

1. 三个学习目标能否被观察和评分，且难度符合导论课。
2. 定义、公式、代码和图是否一致；类比是否明确其失效边界。
3. 先修是否已在前序讲次建立；核心、支持、预览和扩展资源是否分清。
4. 工程案例是否真实但不过度承诺，跨学科连接是否确实出现在被链接材料中。
5. 主动任务是否要求学生先预测、解释或构造证据，而不是只向 Agent 索取答案。
6. 若通过，将审查者、日期和范围写入 front matter；若未通过，保留 `needs-review` 并记录具体问题。
